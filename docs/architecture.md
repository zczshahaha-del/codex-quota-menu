# 项目结构

应用使用 AppKit `NSStatusItem` 提供菜单栏入口，并用透明、无边框 `NSPanel` 承载 SwiftUI 额度卡片，最低支持 macOS 13。这样可以避免系统弹窗与玻璃卡片形成双层背景。

## 数据流程

1. 应用定位本机 ChatGPT/Codex 内置的 `codex` 可执行文件。
   优先使用 `CODEX_BINARY`；随后检查应用包内的 `Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex` 和旧版 `Contents/Resources/codex`，最后检查常见 CLI 安装位置与 `PATH`。
2. 启动 `codex app-server --stdio` 子进程。
3. 通过逐行 JSON-RPC 完成 `initialize` 与 `initialized` 握手。
4. 调用 `account/rateLimits/read`。
5. 解析 `rateLimitsByLimitId`，以 `codex` 桶作为菜单栏主数字。
6. 收到 `account/rateLimits/updated` 通知或到达一分钟刷新周期时重新读取。

每次连接使用独立标识，旧连接的回调不影响新连接。初始化与额度请求均设 20 秒超时；初始化失败或超时会清理子进程，下一次手动或自动刷新重新连接。同一时间只保留一个额度请求，重复刷新合并到当前请求，响应需匹配当前请求 ID。

解析器仅保留要展示的额度，不构建其他模型列表和读取时间；优先选择 `codex`，保留旧版返回格式及缺失主桶时的备用选择。菜单栏和卡片统一选择 `primary`，缺失时回退到 `secondary`。读取失败或断开连接后结束刷新并安静保留上次结果，不维护界面不用的连接/错误状态，没有历史结果时显示中性的占位符。客户端错误日志只保留末尾 64 KiB；自动刷新与手动重试不变。

应用不直接读取 `~/.codex` 中的凭据文件。身份验证由 Codex 子进程使用现有登录状态完成。

## 今日 token 用量

`DailyTokenUsageReader` 只读 `CODEX_HOME`（默认 `~/.codex`）中的 `sessions` 与 `archived_sessions` JSONL 会话记录。优先使用逐请求的 `token_usage_record.usage`，按 `response_id` 去重；旧格式的 `event_msg/token_count` 按累计计数增量计算，配对及重复事件不重复统计。旧请求不会回退累计基线，真正的新计数周期允许重置。首条旧格式记录优先使用 `last_token_usage`，避免把继承的累计量算入当天；分叉会话的创建时间之前的复制记录不计入。合计为输入加输出，缓存及推理计数不额外相加。

日期边界使用系统当前时区的自然日。扫描在独立后台队列执行，内存缓存每个文件的读取位置、上一累计值和当天用量；后续刷新仅读取追加部分，保留未写完的一行，文件替换或截断时重建缓存。跨天重新计算，新日期数据就绪前不显示昨日结果。大段聊天及工具输出行不解析、不缓存；所有统计和去重均在本机完成。读取失败时保留同日上次用量，无记录时显示中性占位。

每次刷新检查目录标识和修改时间，未变化的目录复用成员列表；文件仍检查大小、修改时间和标识，以发现追加、替换或截断。只有用量事件增删、文件新增/删除/重建或日期变化才重建全局去重汇总；追加普通聊天记录不触发重算。模型收到与上次相同的用量不发布新的界面更新。
